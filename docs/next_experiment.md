# 下一個能力實驗：系統能否自己發現問題定義有誤

**實驗設計草案，尚未選定正式題目。**具體題目、正式 baseline、計算與工具預算、成功門檻及失敗判準，仍需在執行前收斂與固定。這份文件沒有宣告第一個能力實驗已開始。

前一階段建立了可核對的運算與保存接續。下一階段要問：系統能不能自行發現原本的問題定義不足，提出新的表示或機制，設計能推翻它的實驗，再把有效改變保留到新問題中？

這比答對一道題更嚴格。即使系統會在提示「你錯了」後改答案，也不能由此認定它在過程中自行發現並修正問題定義。

## 題目如何選

初次題目需要小到可以完整核對，又確實包含「原問題的假設或表示不足」這個困難。單純把加法誤寫成乘法，只能測錯誤定位與修正，不能當成創造新表示或重新定義問題的能力證據。

選題時需要符合：

- 原問題含有可指出的限制或隱含假設，現有表示難以解釋全部觀測。
- 保留可辨識的原始目標；系統不能任意換成更容易的任務，然後宣稱解決問題。
- 允許提出新的變量、表示、機制或方法，而且候選能產生彼此不同的可檢驗預測。
- 觀測、工具與環境規則可以固定版本；評估者能檢查正確性，系統不能直接讀隱藏答案。
- 有提出候選用的資料，也有未公開給候選的新條件，能檢查過度擬合與轉移。
- 原底座與可變研究分支可以明確區分；改變可保存、恢復與消融，並測試既有能力是否退化。

如使用研究者設計的合成環境，成功只能支持該環境內的機制發現。要宣稱發現人類未知的知識，還需要在真實領域另設更嚴格的檢驗。

## 驗證順序

1. **模型自己指出矛盾。**沒有「原題有錯」提示，系統從原始觀測發現具體、可重複的矛盾，並提出哪些假設可能有問題。
2. **模型自己提出候選。**記錄它形成的新問題定義、變量或機制。要能看出表示或可求解範圍如何改變；只是換句話說、改常數或重寫答案不能算。
3. **先留下可區辨的預測與測試。**在看到判定用結果之前，提出能區分原解釋與新候選的實驗，也保留可能推翻新候選的反例。
4. **對照與消融。**在資訊、工具與預算相同的條件下比較，移除關鍵元件或機制，檢查它是否真的參與改進；必要時用組合消融檢查交互作用。
5. **驗證實際改變與保存恢復。**核對實際執行、梯度、參數或方法改變，保存後結束程序，再由新程序恢復，避免把當次文字記憶當成持久改變。
6. **新題再用及舊能力退化。**清空研究當次對話與臨時資料，在未提示的新問題中檢查新方法能否繼續有效，並對照更新前的舊能力是否受損。

工具原始結果、模型原始候選、失敗候選、拒絕原因、超時及回溯都要留下。host 不能把模型提案重寫得更合理後，再歸為模型的自主發現。

## 想像、第一性原理與消融各做什麼

想像用來提出尚未採用的表示或機制；它是候選的來源。第一性原理檢查依明示的基本約束，排除量綱不一致、與可驗證守恆條件相衝突或無法實現的候選。約束本身也要標示為環境規則或研究假設，不能直接當成對所有現實的證明。

消融用來檢查元件是否有因果作用。它可能因冗餘、元件互相補償、交互作用或介入後分布變化而沒有足夠辨別力；不能保證一次拆解就找到所有根因。定位到可能問題後，仍要以新的區辨實驗檢查替代解釋。

新機制的接受依據是事先留下的預測通過新觀測與反例檢查。文字說明流暢、訓練 loss 下降或某個 hash 正確，都不能代替能力結果。

## 待固定的對照

| 對照方向 | 用來排除哪種替代解釋 |
|---|---|
| 凍結模型、固定原問題定義 | 既有模型是否原本就能做，或單純增加觀測便足夠。 |
| 凍結模型加文字自我檢查 | 能力是否只來自額外提示與更多推理時間。 |
| 允許形成新問題，但不保存改變 | 成功是否只存在於當次上下文。 |
| 完整候選流程 | 問題重定義、實驗、更新與保存能否共同形成可重用改變。 |
| 完整流程移除關鍵紀錄或介入元件 | 提出的運算檢查與因果定位元件是否實際參與改進。 |

這些是對照方向，還不是已選定並執行的 baseline。正式比較需要讓相近方法保留其正常的記憶、反思、搜尋與保存成果能力，不能只用削弱過的替代方法。各組使用同一底座、同等工具權限與觀測資訊，並把觀察、介入、訓練、保存與恢復成本計入總預算；也需要預先定義如何測量新題能力及舊能力退化。

如果只有單一成功案例、對照同樣成功，或實際研究決策是外部腳本代替模型做的，應縮小結論。環境版本、工具契約、seeds、預算、資料切分、評分方式及成功條件，不能在看到結果後補定。初次結果無論成功或失敗都保留，再決定下一輪實驗，不把一次通過升格為通用自我進化。
