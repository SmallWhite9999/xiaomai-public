## 中文

### 這週做成了什麼

小麥建在開源模型 ORNITH-1.5-9B 上。目前 9B 底座保持凍結，只更新 25 份研究參數張量；每份張量包含多個數值。這週確認了兩件事：

- **存檔讀回來，核對的數字都沒變。**研究參數改動後存檔，再用全新啟動的程式讀回，核對的約 296 萬個數字逐位元相同（比對範圍見技術紀錄）。
- **重開兩次，核對的狀態與梯度相同。**從同一個存檔各自重開、再往下算一步，兩邊約 311 萬個數字逐位元相同（上圖）。這只比對這一步，不代表文字生成或解新題也一樣。

我之後想檢查的是：小麥留下的改變，重開之後還在不在、換一道題還能不能用。如果存檔本身會出錯，這些檢查都沒有意義，所以這週先把存檔顧好。另外又有更多基本運算（softmax、log、sigmoid 等）改寫成每一步都看得到的版本，目前只在 CPU 上的小型測試和原版對過。

### 沒做成的

**10/7，讓模型自己提出研究方法，這次被格式擋下。**我讓真模型自己寫一個想試的研究方法，連同它預期會看到的數字。模型確實寫完了，但第二個預測值寫成了帶引號的 `"-1.0"`，系統只接受數字，整份提案被拒收，沒有留下任何方法。

``` 節錄：模型實際寫出的第二個預測值。這個值尚未收進公開的十月摘要，原始紀錄可供學術審查核對
模型　predictions 第 2 個值："-1.0"（帶了引號，變成文字）
系統　✕ 拒收　FINITE_NUMBERS_REQUIRED（預測值必須是數字）
```

就算格式修好，這個方法能不能執行、有沒有用都還沒檢查。這次照事先定好的規則判為失敗，不會事後放寬規則改判。

其他還卡著的：

- 開著完整追蹤跑一次太慢，最近一次跑滿 3 小時上限被停掉，原因還沒查清。
- 新改寫的五種機率運算，還沒在真模型上完整驗證；9B 本體大部分也還沒改成看得見的版本。
- 小麥自己改寫的完整文字生成，還沒在 GPU 上跑過。

### 接下來

研究實驗恢復後，依序做三件事：

- 查清開著追蹤為什麼這麼慢。
- 在真模型上補驗這週新改寫的運算。
- 處理格式問題（解析規則不放寬，也不替模型改回覆），再讓模型提一次方法。這次要看的是它能不能把方法存下來，重開後還能用。

## English

### What we got done

Xiaomai is built on the open-source ORNITH-1.5-9B model. For now the 9B base stays frozen, and only 25 sets of research parameters in a separate research branch change. Two things were confirmed this week:

- **A save reads back with every checked number unchanged.** After the research parameters changed and were saved, a freshly started program read them back; about 2.96 million checked numbers matched bit for bit (the technical record gives the exact scope).
- **Two restarts, identical next step.** Restarting twice from the same save and computing one more step gave the same 3.1 million numbers, bit for bit (figure above). This compares that one step only, not text generation or new problems.

What I want to test later is whether a change Xiaomai keeps is still there after a restart and still useful on a new problem. If the save itself were unreliable, none of those tests would mean anything, so this week went into making the save solid. More basic operations, such as softmax, log and sigmoid, were also rewritten so every step can be seen. So far they have only been checked against the originals in small CPU tests.

### What didn't work

**On October 7, letting the model propose its own research method failed on a format error.** I asked the real model to write a research method it wanted to try, along with the numbers it expected to see. It did write one, but its second prediction came out as `"-1.0"`, in quotation marks. The system only accepts numbers, so the whole proposal was rejected and no method was kept.

``` Excerpt: the model's actual second prediction. This value is not yet in the public October summary; the original record is available for academic review.
model   2nd value in predictions: "-1.0" (quoted, so it became text)
system  ✕ rejected  FINITE_NUMBERS_REQUIRED (predictions must be numbers)
```

Even with the format fixed, whether this method runs or helps has not been checked. This attempt stays a failure under the rule set in advance; the rule will not be relaxed after the fact.

Also still stuck:

- Running with full tracing is too slow. The latest run hit its 3-hour limit and was stopped; the cause is not yet known.
- The five newly rewritten probability operations have not been fully checked on the real model; most of the 9B model is not yet rewritten into a visible form.
- Xiaomai's own rewritten text generation has not run on a GPU yet.

### What's next

When experiments resume, three things come first:

- Find out why tracing is so slow.
- Check this week's new operations on the real model.
- Deal with the format problem (the parsing rule stays as is, and replies are not edited for the model), then let the model propose a method again. This time the question is whether it can keep the method and still use it after a restart.

## 技術紀錄

### 本週完成

- 版本：10/9 起的正式存檔是研究權重第 8 版，沿用 True 1.2（9/22 標記）的研究線名稱；之後的兩個新存檔沒有升格。版本名稱本身不表示完整狀態等價；升版時另附正式入口、冷恢復核對範圍及發版說明。存檔傳承紀錄在私人 repo，可供學術審查核對。其中 9/23–9/24、9/30–10/1 尚缺逐檔指紋，不能宣稱整條傳承已完成逐位元核對；版本名稱也不表示全部原始模型權重或執行狀態均未改變。
- 10/6–10/7：R13、R14、R16 在 CPU 上把 sigmoid、softplus、投影、分組卷積、rsqrt 與 SiLU 的反向計算接上 Python Tape 與 AdamW，可追蹤。範圍是限定算子與尺寸的 CPU 核對。
- 10/7：R15 在 A100 上讓真模型生成方法提案，兩組設定各產生 144 tokens、自然結束，原始回覆與 token IDs 完全相同，共 2 次生成，只有 1 份不同提案，不能算成兩份獨立提案。第二個預測值是字串 `"-1.0"`，原解析器以 `FINITE_NUMBERS_REQUIRED` 拒收，沒有保存方法。
- 10/7：R17 用凍結 9B 在 GPU 上算出的特徵，完成研究更新、Python Tape 反向、AdamW 更新與保存，25 份研究參數張量改變；兩個保存點各由新程序讀回核對。
- 10/8：R18–R19 把 exp、log、softmax、log_softmax、logsumexp 與 rsub 接上同一張 Python Tape，完成合成資料的 CPU 數值、追蹤開關與存檔後第二步核對。
- 10/9（R19-A100）：指定的研究保存點，在兩個獨立新程序中各接著做下一筆研究更新，結果逐位元一致；這兩個新保存點沒有自動升為正式入口。同日完成停點備份。
- 10/10–10/11：公開十月進度、研究定位與來源修訂（[5ad2e49](https://github.com/SmallWhite9999/xiaomai-public/commit/5ad2e4901a3188e2a2ef24c39ec2990d2427ea30)、[cb12b77](https://github.com/SmallWhite9999/xiaomai-public/commit/cb12b7787b61815b02019fe4ef199366603b9581)）。文件發布不算新的模型實驗。

### 驗證與數字

- R17 原生與關閉追蹤兩條路徑：207 筆數值紀錄、3,108,566 個值都在預定容差內，其中 81 筆非逐位元一致。兩次冷恢復各核對 181 筆研究狀態、2,960,497 個值，逐位元一致；不含完整 CUDA 亂數狀態與全部延遲載入的底座值，這一批也沒有執行下一筆更新。
- R18–R19：三組合成初始化、177 個參數元素，和原生自動微分加相同 AdamW 比較，最大差約 1.2e-7；追蹤開關逐位元一致；六個新程序讀回存檔後的第二步一致。全為 CPU 合成測試。
- R19-A100：兩個新程序比較 206 筆含型別與形狀的紀錄（181 筆存檔後狀態、25 筆新梯度），共 3,108,565 個純量值逐位元一致。範圍是這一筆研究更新，不代表任意輸出、文字生成或 9B 全模型反向等價。R17 的 207 筆計數另含 1 個下一步損失純量；R19-A100 的 206 筆逐位元計數只統計含型別與形狀的狀態與梯度，損失另有比較，不列入這個計數。這是兩批紀錄的計數差異，不能據此認定兩批使用相同狀態。
- 公開摘要不含模型權重、保存點與完整原始紀錄，無法只靠公開 repo 重現完整流程；學術審查或合作討論時可提供核對。

### 失敗與未完成

- R15：兩組真模型嘗試自然結束，成本與執行安全通過審查，但有效方法的保存、獨立執行與新題比較都沒有完成。執行安全通過不等於方法能力通過。
- 完整追蹤開／關的核對未完成。最近一次開啟追蹤的診斷達 10,800 秒上限，先後收到 SIGINT、SIGTERM，以 -15 結束；耗時原因未判定。
- 新增五個機率算子在真模型研究參數上的梯度與更新等價，尚未核對。
- 9B 底座的 Python 前向、反向與更新尚未完成；已盤點 799 份參數，盤點不等於能執行。
- sqrt 新候選的 GPU 核對、BF16 機率運算與完整邊界待驗。修正後的文字生成候選通過 CPU 預檢，GPU 尚未啟動。

### 下一步
